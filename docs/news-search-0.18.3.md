# 0.18.3 专项资讯检索修复

旧请求对行业/公司关键词检索只返回通用失败警告，调用方无法分辨接口拒绝、合法空结果和部分备用资讯。修复按[东方财富官方搜索前端](https://so.eastmoney.com/newstatic/js/page/search_main.js)的 `searchZiXun` 契约构造 JSONP 请求：显式回调、非空 `<em>` 高亮标签、`cmsArticleWebOld` 类型及 `param` 参数。按发布时间排序读取首屏8条，不宣称来源的封顶命中总数是完整资讯覆盖。

每条专项结果保留实际发布时间、来源文章URL、原始文章标识、检索词和可见标题/摘要的命中位置。结果明确为 `metadata`，`relationVerified=false`：代码和公司名称都可能发生全文字面误匹配，必须人工确认关联和原文，不能自动变成五类证据或双人复核票。缺少有效标题、时间或受信来源URL的结果拒绝使用；不编造首页URL填充文章链接。

各源返回独立状态、错误和HTTP状态，区分 `empty` 与 `failed`；广泛市场快讯部分失败不阻断成功的专项查询。`stock_detail`、行业采集及研究资讯视图保留覆盖诊断。新浪市场快讯仅是广泛资讯备用，不能代替公司/行业专项原文；快讯端错误仍保留。

## 验证

- 新增10项脱敏测试，验证官方请求参数、JSONP安全解析、元数据时刻与关联边界、源隔离、合法空结果、HTTP失败、超时、损坏内容、无效文章及冲突总量。
- 271项完整插件回归通过，串行合成测试运行在512 MiB cgroup内，峰值约440 MiB；合成容量用例使用256 MiB测试堆，真实核验启动器仍保持128 MiB堆限制。
- 真实专项查询：行业名、公司名及6位股票代码各取得8条有来源时间的结果。代码查询中可见非公司专属的全文匹配，因此没有宣称证券身份已核实。
- DSH `0.2.1-rc.5` 的真实 Cordis/ToolRuntime 注册17个工具，参数校验、模拟行业分页及PNG导出通过；使用独立临时profile，不改用户资料，不触发模型。
- Cindy与DSH共用此数据源修复。SDK测试、npm打包/发布、市场受理/审核和正式计划端到端验收是不同事实，分别记录。
